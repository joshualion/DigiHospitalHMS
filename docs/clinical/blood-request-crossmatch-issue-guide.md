# Blood Request, Crossmatch and Issue Guide

This guide describes the configured software workflow. It is not a clinical compatibility rule set.

1. Create the blood request with patient, facility, clinician, requested component, quantity, indication, priority and required date/time.
2. Submit and accept the request according to local authorization practice.
3. Collect the patient specimen. Confirm patient name and identifier, print/use the generated specimen label and record custody details.
4. If an identity or label discrepancy is found, mark it as discrepant and stop. Do not continue testing, reservation or issue until authorized governance resolves it.
5. Enter patient ABO/Rh manually from the specimen result. A second authorized user must verify it.
6. If the patient group conflicts with a prior verified group, the request is hard-stopped for blood-group discrepancy resolution.
7. Enter compatibility or crossmatch results manually. A second authorized user must authorize the result.
8. Select components only from available released stock. The application blocks expired, recalled, wrong-type or already reserved components.
9. Reserve one or more components. Partial reservation is allowed and outstanding quantity remains visible.
10. Issue reserved components after authorized compatibility testing, or after explicit emergency-release authorization and justification.
11. Print issue documentation for the receiver and destination handoff.
12. Return to stock only after an authorized suitability assessment and documented reason.
13. Reverse an issue only through the controlled reversal action. History remains visible.

Deferred from this phase: bedside transfusion administration, transfusion observations, reaction management, analyzer integration and automated compatibility decisions.
