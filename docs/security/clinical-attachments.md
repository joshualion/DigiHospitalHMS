# Clinical Attachments Security

Status: Phase 4B baseline.

Radiology support attachments are stored on a private disk and are never served from public web storage.

## Accepted Files

The current implementation accepts only:

- PDF.
- JPEG.
- PNG.
- WebP.

The server validates Laravel upload rules, extension and detected MIME type. Filenames are generated by the server. SVG, executable files and DICOM studies are not accepted in this phase.

## Quarantine Boundary

Uploads start with `scan_status = quarantined`. Quarantined files cannot be downloaded. A cleared status is required before access.

The malware-scanner boundary is intentionally explicit: a future scanner integration should inspect the private file and call the controlled clearance path only after passing configured checks. This phase does not pretend to verify external malware scanning.

## Access

Files are downloaded through authorized controllers. Access requires permission to view the scoped radiology request. Download attempts are logged.

## Deletion And Retirement

Released report attachments cannot be deleted. Unreleased active attachments can be retired with a reason, actor and timestamp. Physical hard deletion is outside the active workflow.
